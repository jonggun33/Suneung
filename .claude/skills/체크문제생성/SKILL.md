# 체크문제 빌더

과목별 `out/체크문제` 폴더에 최고난도 융합 응용문제를 생성하는 스킬. `요약본작성`이 만든 `요약본.md`(단일 누적 파일)와 `문제은행` 에이전트가 만든 `문제은행/db.md`를 입력으로 쓴다. 이 스킬은 앞의 두 스킬/에이전트와 달리 append나 누적 개선이 아니라, **호출할 때마다 새 파일을 만든다.**

## 입력

- `subject`: 대상 과목 (예: `수학`). 명시 안 되어 있으면 사용자에게 확인한다.
- `개수`: 이번에 만들 문제 수. **항상 시작할 때 사용자에게 물어본다** (사용자가 이미 개수를 명시한 경우는 다시 묻지 않는다).
- `{subject}/out/노트/요약본.md`: 최신 요약본 (단원별 공식/개념, 오답 인사이트·취약점 포함)
- `{subject}/in/문제은행/db.md`: 누적된 문제 목록

## 규칙

1. **최고난도, 융합형.** 문제마다 단일 단원이 아니라 요약본에 정리된 서로 다른 단원/영역의 개념을 최소 2개 이상 결합한 응용문제를 만든다. 난이도는 수능/모의고사 최고난도(킬러 문항) 수준을 목표로 한다.
2. **근거 자료 활용.** 요약본의 단원별 공식·개념과, 특히 오답 인사이트에서 드러난 취약 영역을 우선적으로 반영한다. 문제은행에서 소재/스타일이 유관한 기존 문제(항목번호)를 참고하되 그대로 베끼지 않고 변형·응용한다. 문제를 여러 개 만들 때는 서로 다른 취약 단원/조합을 겨냥해 겹치지 않게 한다.
3. **문제와 정답을 분리.** 한 실행에서 만든 문제 전체가 같은 타임스탬프를 공유하는 두 개의 파일(문제 파일, 정답 파일)에 함께 담긴다. 문제 파일에는 정답이나 풀이가 절대 포함되면 안 된다.
4. **파일명은 `체크문제_날짜시간` 형태.** 형식: `체크문제_YYYYMMDD_HHMMSS`. 매 실행마다 새로 생성하며 기존 파일을 덮어쓰지 않는다. 문제 개수와 무관하게 실행당 파일 쌍은 하나다.

## 절차

1. `subject`와 `개수`를 확인한다. `개수`가 없으면 사용자에게 몇 문제를 만들지 물어본다.
2. `{subject}/out/노트/요약본.md`와 `{subject}/in/문제은행/db.md`를 읽는다. 요약본이 없으면 `요약본작성`을 먼저 돌리라고 안내하고 중단한다.
3. 요약본의 단원별 공식/개념과 오답 인사이트(취약 단원, 오답원인 분포)를 파악한다.
4. 요청받은 문제 수만큼 반복해서 각 문제를 설계한다. 문제마다:
   - 융합할 단원/영역 2개 이상을 정한다 — 가능하면 취약점으로 지목된 단원을 최소 하나 포함시킨다. 여러 문제를 만들 때는 겨냥하는 단원 조합이 서로 겹치지 않게 한다.
   - 문제은행에서 참고할 기존 문제(항목번호)를 1개 이상 골라 소재·발상을 참고한다.
   - 최고난도 응용문제를 작성한다: 문제 지문, 필요한 조건/그림 설명(있으면), 보기/선택지(객관식이면) 또는 답 형식 안내(단답형이면).
5. 현재 시각을 `YYYYMMDD_HHMMSS`로 얻어 두 파일을 만든다:
   - `{subject}/out/체크문제/체크문제_{timestamp}_문제.md`
     ```
     # 체크문제 ({생성일시})

     ## 문제 1
     - 융합 단원: {단원A}, {단원B} ...
     - 참고 문제은행 항목번호: #n
     - 난이도: 최고난도(킬러)

     {문제 지문 및 보기}

     ## 문제 2
     ...
     ```
   - `{subject}/out/체크문제/체크문제_{timestamp}_정답.md`
     ```
     # 체크문제 정답/해설 ({생성일시})
     - 대응 문제 파일: 체크문제_{timestamp}_문제.md

     ## 문제 1 정답
     {정답}

     ### 해설
     {단계별 풀이. 어떤 단원/공식이 어디서 쓰였는지 명시}

     ### 이 문제를 만든 이유
     {요약본의 어떤 취약점/인사이트를 겨냥했는지}

     ## 문제 2 정답
     ...
     ```
6. 만든 문제 수, 두 파일 경로, 문제별로 겨냥한 취약 영역을 요약 보고한다.
