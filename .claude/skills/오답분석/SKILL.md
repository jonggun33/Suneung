# 오답 DB 빌더

`in/오답`에 쌓인 오답 파일들을 읽어서 `in/오답/db.md`에 append-only로 기록하는 스킬. `문제은행` 에이전트와 같은 append-only 원칙을 따르되, 오답 원인 분류는 기계적으로 판단할 수 없으므로 반드시 사용자와의 대화를 통해 확정한다.

## 입력

- `source_folder`: 대상 과목의 `in/오답` 폴더 (예: `수학/in/오답`)
- `db_file`: `source_folder/db.md`

과목이 명시되지 않았으면 사용자에게 물어본다.

## 규칙

1. **Append-only.** `db_file`에 이미 있는 섹션은 절대 수정·삭제하지 않는다. 원본 파일이 나중에 지워져도 DB 기록은 그대로 둔다.
2. **새 파일만 처리.** `db_file`에 `## 출처: <파일명>` 섹션이 이미 있으면 건너뛴다.
3. **항목번호는 DB 전체 일련번호.** 파일이 바뀌어도 리셋하지 않고 이어서 증가시킨다. `db_file`에서 마지막 항목번호를 찾아 다음 번호부터 부여 (DB가 비어 있으면 1부터).
4. **시험이름 필수.** 파일명/본문에서 추론하고, 확인이 안 되면 `시험이름: 확인필요`로 표시 후 요약에 flag.
5. **오답원인은 반드시 사용자에게 확인.** 절대 추측만으로 채우지 않는다. 아래 4개 값 중 하나만 허용:
   - 계산실수
   - 문제오해
   - 접근법몰라
   - 시간부족

## 절차

1. `db_file`이 없으면 `# {과목} 오답 DB` 헤더로 생성한다.
2. `db_file`을 읽어 이미 처리된 파일명(`## 출처:`)과 마지막 항목번호를 파악한다.
3. `source_folder`의 파일 목록에서 새 파일을 찾는다. 없으면 "새 오답 파일 없음"이라고 보고하고 종료한다.
4. 새 파일마다(파일명 순):
   a. 내용을 읽어 개별 오답 문항을 추출한다: 문제(지문/요약), 학생이 쓴 답, 정답.
   b. 문항별로 `AskUserQuestion`을 사용해 오답 원인을 사용자에게 확인한다. 질문에는 문제 요약, 학생 답, 정답을 함께 보여줘서 사용자가 바로 판단할 수 있게 한다. 선택지는 위 4개 값 그대로 제시한다(라벨 순서는 자유). 한 번에 최대 4문항까지 질문에 묶어 물어볼 수 있다.
   c. 사용자 답변을 받은 문항부터 순서대로 `db_file`에 append한다 (Edit로 파일 끝에 추가, 전체 재작성 금지):
      ```
      ## 출처: {파일명}
      _추가일: {오늘 날짜, YYYY-MM-DD}_

      ### 항목번호: {n}
      - 시험이름: ...
      - 문제: ...
      - 학생 답: ...
      - 정답: ...
      - 오답원인: {계산실수|문제오해|접근법몰라|시간부족}
      ```
5. 모든 파일 처리가 끝나면 요약을 보고한다: 추가된 파일 수, 문항 수, 오답원인별 개수, flag된 항목(시험이름 확인필요 등).
